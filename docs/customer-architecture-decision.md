### Why this choice

The database supplies atomic version checks, uniqueness, immutable snapshots and an outbox; private Storage supplies independently authorized photo objects. The same provider supplies the requested customer auth flow. Netlify remains the selected host and existing owner login remains useful. This avoids a Netlify plan migration and keeps the first staging test separate from production Pesmera data.

Netlify can support persistence, but static files and Functions do not make these contracts durable. [Netlify Blobs](https://docs.netlify.com/build/data-and-storage/netlify-blobs/) supports persistent site stores and private server access, but ordinary multiple-key writes are not a substitute for relational transactions/outbox uniqueness. Its documentation directs concurrency/relational use cases toward databases; site-wide stores are shared across deploy contexts, so preview isolation must be deliberate. [Netlify Database](https://docs.netlify.com/build/data-and-storage/netlify-database/) supports managed Postgres and preview branches, but is documented for credit-based plans. The team API reports Pro/`nf_team_pro`; it does not establish credit-based eligibility or a configured database. Treat that as unknown, not free/included. No Netlify database was found/configured through the available project metadata.

## Review findings fixed in PR #2

- Missing/nonfinite/string assignment expiry previously failed open; now rejected. Key tuples are encoded rather than delimiter-concatenated, and auth-provider namespaces prevent subject collisions.
- Client evidence-shaped `safe:true` photo argument was an unsafe future API contract. Completion now invokes an injected server verifier, binds object ID/customer key/hash/size/MIME, rechecks revocation/expiry after awaiting, and rejects removed-item/duplicate photo associations. Begin-upload quota is bounded. Actual scanning and object verification remain absent.
- Previously any notion-domain URL plus `verified:true` could certify an unrelated record. Receipt now binds exact ID/digest and checks canonical path/domain. The real adapter still must read back the destination rather than assert its own success.
- Pending delivery had no recovery lease. Synthetic attempts now expire, retry the same ID/payload and use attempt fencing to prevent obsolete responses overwriting a newer result. Durable transactional leases and remote create reconciliation remain adapter work.
- Rollback reused old versions, risking stale-version replay. It now advances version and retains deletion tombstones/audit.
- Added an **unwired** handler factory that resolves the server principal, rejects body identity, checks mutation origin, limits streamed UTF-8 request bytes and redacts failures. Live endpoint is still unconditional 503. No client role/email is trusted.
